## Issues

### QA-001 — NBA home date controls do not change the games being shown

**Severity:** High  
**Area:** NBA home page / scoreboard

#### Evidence

The earlier tester clicked **Yesterday** while investigating the scoreboard, then recorded that the games API returned two NBA games while the home scoreboard showed none. Their supplied screenshots are the source of this observation.

The current code confirms that the three date buttons only update the `dateFilter` state:

- `src/pages/nba/NBAHome.jsx:167` — Yesterday sets `YESTERDAY`
- `src/pages/nba/NBAHome.jsx:173` — Today sets `TODAY`
- `src/pages/nba/NBAHome.jsx:180` — Tomorrow sets `TOMORROW`

`dateFilter` is never subsequently used to fetch, filter, or render a different set of games. The page always fetches only `/api/games/today` (`src/pages/nba/NBAHome.jsx:43`), and the only implemented filters are All, Live, Eastern, and Western.

The API response also has no date field (`backend/adapters/espn_nba.py:128-141`), so the frontend currently has no per-game date available to implement client-side date filtering.

#### User impact

Selecting Yesterday or Tomorrow visibly marks a different button as active, but leaves the same data in place. On days without games this can present an empty scoreboard even though the user believes they selected a date that has games. It also makes the date navigation misleading.

#### Reproduction

1. Open the NBA home page.
2. Note the games in the scoreboard.
3. Select **Yesterday** or **Tomorrow**.
4. Observe that only the button styling changes; no new request or date-specific games are loaded.

#### Suggested fix

Add a date-aware games endpoint (or accept a `date=YYYYMMDD` query parameter), include the event date in each returned record, and refetch/re-render when `dateFilter` changes. Add automated coverage for all three date selections, including an off-day response.

### QA-002 — NBA Seasons page contains hard-coded, time-sensitive data

**Severity:** Medium (data accuracy)  
**Area:** NBA Seasons

#### Evidence

`backend/adapters/espn_nba.py:461-473` returns a fixed list of seasons rather than live or maintained data. It labels the **2025–26** season as “In Progress” and “TBD”. As of this test date (October 10, 2026), that is no longer current, while the rest of the app is serving 2026–27 NBA standings and schedule data.

Several historical MVP and champion values are also embedded directly in source, which makes corrections and new seasons impossible without a deployment.

#### User impact

Users receive stale and contradictory season information, especially during a new season. The page can conflict with the standings and schedule elsewhere in the same app.

#### Reproduction

1. Open NBA → Seasons.
2. Observe the 2025–26 row marked “In Progress”.
3. Compare with the current-season records shown under NBA Standings or Games.

#### Suggested fix

Replace the static list with a maintained data source, or at minimum move it to reviewed content/configuration and update it each season. Derive the in-progress season from the current league season rather than a hard-coded label.
